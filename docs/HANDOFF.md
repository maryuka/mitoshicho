## 2. 決まっている仕様（ユーザー確認済み）

- 呼び方は「月」（今月＝10/15〜11/14 のような給料日始まりの範囲）。「期」とは言わない
- 日々の記録は家計簿アプリ（Zaim など）。アプリに記録機能は持たない。実績は「月 × カテゴリの合計」を月末に手入力（Zaim API・Zaim CSV 連携は見送り）
- 下部メニューはホーム／計画／ふりかえりの3つ（3つ以下が希望。計画＝月ごとの予算、ふりかえり＝月末の実績入力）。上部のヘッダーは置かない。左上の丸いメニューボタン（☰）から左に出るメニューに、立替・各設定・取り込み・バックアップをタイルで並べ、開いた先は「‹ タイトル」だけのページ（ユーザーが参考に挙げた家計系アプリの形）
- 給料日は専用タブではなく、ホームの「ふだん／給料日」切り替え（「モード」とは書かない）
- 年間表（表形式）・この先のバッファ・ホームの前月振り返りカードは不要と言われて削除済み
- カードは毎月の引落日・請求確定日を持ち、確定日を過ぎて未入力ならホームの「やること」に出す
- その月だけ予算を変えるのは「計画」でカテゴリを開いて項目の欄に入れる（今のままで OK とのこと）
- データ欄からは元のスプレッドシート（年間お金計画表）の CSV を取り込める
- タッチ端末ではダイアログを開いても入力欄に自動フォーカスしない（キーボードが出るのが嫌）
- アプリ名の表記は「家計の見通し帳」（ホーム画面用の短い名前は「見通し帳」）。コンセプトは「先が見えるから、今を気持ちよく使える」
- デザインは狐のイラストを使い、オレンジと黄色。ライトの主色 `#ea7d12`、ホーム上部の帯 `#f7a531`。ダークは背景を黒に近い無彩色（`#0b0b0c`）にし、茶色っぽさは出さず、オレンジと黄色はアクセントだけ。文字は丸ゴシック（Zen Maru Gothic）
- データが空のときは「ようこそ」のウォークスルー（5ページ、`src/features/welcome/`）。データが空のあいだは下のメニューを出さない。サンプルデータは入る内容を見せるダイアログ（`SampleDataDialog`）を通して入れる
- イラストは `src/assets/kitsune/` に同梱。バッファ不足のときはホームの狐が困った顔になる

## 3. 次にやること（未決）

**ホームの中身の見直し（話し合いの途中）**
ユーザーの声:「バッファが見たいわけじゃない。何がホームにあると嬉しいか」。
こちらから出した案（ユーザーの回答待ち）:
1. やること（カード請求の入力・先月の実績入力・送金チェック）
2. 今月の予算一覧（カテゴリごとの使っていい額。家計簿アプリと見比べる用）
3. この先数か月の「いつもと違うこと」（年会費、予算を変えた月、分割・ローンの完済まであと何回）
4. 引き落とし予定（日付・口座・金額）

おすすめとして「1 → 2 → 3 の順、バッファは不足しそうなときだけ警告」を伝えてある。返事を聞いてから作ること。

## 4. 作業上の注意

- **個人情報をリポジトリに入れない**（public）。元のスプレッドシートの名前（借入先・カード名・収入元）や実際の金額は、コード・コメント・テスト・サンプルデータ・コミットメッセージに書かない。サンプルデータとテストは架空の値にしてある。過去に一度、履歴の書き換えと古いブランチの削除で除去している
- 元のスプレッドシートは Google ドライブにある（Drive コネクタで読める）。URL はユーザーに聞くこと。動作確認で使う場合は scratchpad に置き、リポジトリには入れない
- ユーザーとのやりとりは日本語。説明は短めに、決めてほしいことは質問として示す
- コミット・push は依頼の範囲で。`main` への反映は `git push origin HEAD:main`
- このコンテナのネットワーク制限: github.io、api.zaim.net、dev.zaim.net には接続できない。リモートブランチの削除はプロキシに拒否される（必要ならユーザーに GitHub の画面で消してもらう）
- npm で `vitest@4` を入れると依存解決が失敗したため `vitest@3` を使っている
