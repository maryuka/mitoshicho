## 2. 決まっている仕様（ユーザー確認済み）

考え方（サイクル、ずれ、細かく管理しない、残高を持たない、データの方針など）は concept.md の「決まったこと」にまとめてある。画面まわりで決まっていること:

- 呼び方は「月」（今月＝10/15〜11/14 のような給料日始まりの範囲）。「期」とは言わない。貯金と投資はまとめて「積み立て」
- 日々の記録は家計簿アプリ。アプリに記録機能は持たない。実績は「月 × カテゴリの合計」を月末に手入力（Zaim API・Zaim CSV 連携は見送り）
- 1画面1役割。下部メニューはホーム（今やること）／計画（月の予算）／ふりかえり（計画とくらべて考える）の3つ。上部のヘッダーは置かない。左上のメニューボタン（☰）から、給料日のチェック・立替・設定・データの各ページを開く
- ホームは、計画する → 使う → ふりかえる の輪と今やること1つ、お知らせ、この先の大きい出費（近い3件）だけ。余りの推移・±0 の表示・入出金の予定は出さない
- 給料日はホームの切り替えではなく独立したページ。月のはじめ5日はホームの今やることに出す
- ずれは目立つもの（計画の1割か1,000円の大きい方をこえたもの）だけ出す。理由（納得・想定外・なんとなく）とメモは付けたいものだけ。「ふりかえり完了」ボタンで完了にできる（取り消し可）
- 責めない言い方にする。使いすぎを赤字や「超過」だけで伝えない
- その月だけ予算を変えるのは「計画」でカテゴリを開いて項目の欄に入れる。大きい出費は「大きい出費を追加」で、その月だけの項目として入れる
- データ欄からは元のスプレッドシート（年間お金計画表）の CSV を取り込める
- タッチ端末ではダイアログを開いても入力欄に自動フォーカスしない（キーボードが出るのが嫌）
- アプリ名の表記は「家計の見通し帳」（ホーム画面用の短い名前は「見通し帳」）。コンセプトは「先が見えるから、今を気持ちよく使える」。「使いこなすと」のような言い方はしない
- デザインは狐のイラストを使い、オレンジと黄色。ライトの主色 `#ea7d12`、ホーム上部の帯 `#f7a531`。ダークは背景を黒に近い無彩色（`#0b0b0c`）にし、茶色っぽさは出さず、オレンジと黄色はアクセントだけ。文字は丸ゴシック（Zen Maru Gothic）
- はじめて開いたときは、ウォークスルー（3ページ、文字は少なく）→ サンプルデータで画面の案内（保存はしない、1回だけ）。データが空のあいだは下のメニューを出さない
- イラストは `src/assets/kitsune/` に同梱。虫めがねの狐（looking）はふりかえりの場面で使う

## 4. 作業上の注意

- **個人情報をリポジトリに入れない**（public）。元のスプレッドシートの名前（借入先・カード名・収入元）や実際の金額は、コード・コメント・テスト・サンプルデータ・コミットメッセージに書かない。サンプルデータとテストは架空の値にしてある。過去に一度、履歴の書き換えと古いブランチの削除で除去している
- 元のスプレッドシートは Google ドライブにある（Drive コネクタで読める）。URL はユーザーに聞くこと。動作確認で使う場合は scratchpad に置き、リポジトリには入れない
- ユーザーとのやりとりは日本語。説明は短めに、決めてほしいことは質問として示す。ユーザーは見てから決めたいので、実装してスクリーンショットと試用版で見せる
- コンセプトの細かさを読み違えやすい（例: 「プラマイゼロ」は理想のイメージで、数字の目標ではなかった）。迷ったら concept.md の「一言でいうと」と判断の基準に戻る
- このコンテナのネットワーク制限: github.io、api.zaim.net、dev.zaim.net には接続できない。リモートブランチの削除はプロキシに拒否される（必要ならユーザーに GitHub の画面で消してもらう）
- npm で `vitest@4` を入れると依存解決が失敗したため `vitest@3` を使っている

## 5. コードの地図

| 場所 | 中身 |
|---|---|
| `src/domain/period.ts` | 月（期間）の計算。ID は開始月の `YYYY-MM` |
| `src/domain/cashflow.ts` | 予算・カテゴリ実績・カード請求の予測と確定日・振り分け・カードのお知らせ・大きい出費（純粋関数） |
| `src/domain/review.ts` | 計画とのずれ、改善のヒント、ふりかえりの進み具合 |
| `src/domain/payday.ts` | 給料日のチェックの進み具合 |
| `src/domain/importSheet.ts` | 元のスプレッドシート CSV の読み取り |
| `src/db/` | Dexie のスキーマ（v3）、操作、バックアップ、CSV 取り込みの保存、サンプルデータ（`buildSampleData` は保存せずに組み立てる） |
| `src/features/home/` | ホーム（サイクルの輪、お知らせ、大きい出費）と給料日のチェックのページ |
| `src/features/plan/` | 計画 |
| `src/features/review/` | ふりかえり（ずれ・メモ・ヒント） |
| `src/features/budget/parts.tsx` | 計画とふりかえりで使う部品（実績の入力行、カード請求、項目ごとの予算） |
| `src/features/welcome/` | ウォークスルーと、サンプルデータでの画面の案内（`Tour.tsx`） |
| `src/features/receivables/` | 立替・経費精算 |
| `src/features/settings/` | 設定（口座・カード、カテゴリ、定期項目、チェックリスト、データ） |
| `src/components/` | 金額入力（式を計算）、月の切り替え、カード請求ダイアログ、確認ダイアログ、メニュー、狐のイラスト |
| `src/theme.ts` | MUI テーマ（OS のライト／ダークと埋め込み先の `data-theme` に追従）。色はここのトークンを使う |
| `scripts/build-artifact.mjs` | dist を1枚の HTML にまとめる（claude.ai の Artifact 用） |

画面の切り替えは `#home` 形式のハッシュ（`#/home` は Artifact 内で使えないため）。`window.confirm()` も Artifact 内で使えないので、画面内の確認ダイアログ（`confirmDialog`）を使う。
