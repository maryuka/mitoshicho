# 見通し帳 (mitoshicho) 設計書 v0.2

> 個人用の「給料日サイクル型」予算管理アプリ。
> 静的配布 ＋ React ＋ IndexedDB。データは端末内のみ。
> v0.1（たたき台）からの変更点は末尾の「変更履歴」を参照。

---

## 1. コンセプト

> 2026-11 にコンセプトを見直した。これからの方向は [concept.md](concept.md) を参照（この章は v0.3 時点の役割の説明）。

**期ごとに予算を立て、給料日にお金が回るかを確認し、期末に家計簿アプリ（作者は Zaim）の集計で振り返る。画面には特定のアプリ名を出さない。**

- 日々の支出の記録は **家計簿アプリ**（Zaim など）で行う。このアプリでは記録しない。
- このアプリの役割は3つ。
  1. **予算**: 定期項目から期ごとの予算を自動で作る。
  2. **給料日**: 入金・カード請求を確定し、バッファ（余裕）と口座ごとの振り分け額を出す。
  3. **振り返り**: 期末に家計簿アプリのカテゴリ別合計を入力し、予算との差を見る。

### 1.1 元にしたスプレッドシートの困りごとと対応

| 困りごと | 対応 |
|---|---|
| 予定と実績が同じセルで、上書きすると予定が消える | 予算（項目）と実績（カテゴリ合計）を別に持つ |
| 「どれがカード払いか」を数式で手書きしていて、期ごとにずれる | 項目に支払い元を持たせ、カード請求を自動で予測する |
| 数式の参照ミス・`#REF!` | 計算はすべてテスト付きの純粋関数で行う |
| 振り分け額の数式を手書きしている | 口座ごとに自動で集計する |
| 年ごとにシートを複製している | 定期項目から各期へ自動で展開する |
| 年会費がコメントでしか管理されていない | 「毎年◯月」の定期項目にする |
| 期の区切りを途中で変えた | 期の開始日を設定にした |

## 2. 決まったこと（ユーザーとの確認済み）

| 論点 | 決定 |
|---|---|
| 月の区切り | 給料日（15日）始まり。画面上は「月」と呼ぶ（今月＝10/15〜11/14）。設定で変更可 |
| 日々の記録 | 家計簿アプリで行う。アプリには記録機能を持たない |
| 実績の粒度 | **期 × カテゴリの合計**。期末に家計簿アプリを見て手入力する |
| Zaim 連携 | **手入力（案A）**。API は OAuth 1.0a の署名と CORS の問題で静的配布と合わないため見送り。CSV 取り込みは必要になったら検討 |
| 下部メニュー | 3つ以下。現在は **ホーム／予算と実績** の2つ。ヘッダーは置かず、左上のメニューボタンから立替・設定・データの各ページを開く |
| 給料日 | 専用タブではなく、ホームの **給料日モード** に切り替える |
| 年間表 | なし（表形式は見にくい）。期を前後に切り替えて見る |
| この先のバッファ・振り返り | ホームには出さない（振り返りは「予算と実績」で月を切り替えて見る） |
| カード請求 | カードごとに **引落日・請求確定日** を設定できる。期ごとに引落日・確定日・金額を入力できる。確定日を過ぎて未入力なら「やること」に表示する |

## 4. データモデル（IndexedDB / Dexie, schema v3）

金額は整数（円）。期 ID は開始月の `YYYY-MM`。日付は `YYYY-MM-DD`。

| テーブル | 主な項目 | 役割 |
|---|---|---|
| `settings` | periodStartDay, holidayShift, lastBackupAt | 設定（1件） |
| `accounts` | name, kind(bank/card), withdrawDay, confirmDay, withdrawAccountId, billLagPeriods | 口座・カード |
| `categories` | name, kind(income/expense/debt/saving) | カテゴリ（Zaim のカテゴリに合わせて作る想定） |
| `items` | name, categoryId, defaultAmount, day, sourceAccountId, recurrence(monthly/yearly/once), startPeriod, endPeriod | 定期項目（予算の型） |
| `entries` | periodId, itemId, planned, memo | 期ごとの予算の上書き（差分だけ保存） |
| `categoryActuals` | periodId, categoryId, amount | 期 × カテゴリの実績合計 |
| `cardBills` | periodId, cardId, actual, withdrawDate, confirmDate | カード請求の確定額と日付の上書き |
| `receivables` | title, kind, amount, expectedPeriod, receivedAt | 立替・経費精算 |
| `checklistTemplates` / `checklistDone` | label / periodId, key | 給料日のチェックリスト |

- 合計・バッファ・振り分け・カード予測は保存せず、毎回計算する。
- 項目・口座・カテゴリは削除せずアーカイブできる（過去の期の表示を守るため）。
- 旧形式（v1 の Entry.actual、v2 の項目ごとの記録）は、DB の移行とバックアップ復元のときにカテゴリ合計へ変換する。

## 5. 計算ルール（`src/domain/cashflow.ts`）

- **予算**: 項目ごとに「この期の上書き ?? 定期項目の金額（発生する期のみ）」。カテゴリの予算はその合計。
- **カテゴリの見込み額（effective）**
  - 収入: 実績 ?? 予算
  - 支出・返済・貯金（過去の期）: 実績 ?? 予算
  - 支出・返済・貯金（今期以降）: max(実績, 予算)。実績が途中の額でも、残りの予算は出ていく前提で見込む
- **カード請求の予測**: 前期（カードごとに何期ずれるか設定可）の「支払い元＝そのカード」の項目の予算合計。確定額が入ればそれを使う。
- **確定日**: カードごとの毎月の確定日から「引落日より前で直近のその日」を求める。期ごとの入力があればそちらを優先する。
- **バッファ** = 収入 − 口座から出る額 − カード請求 + 立替回収
  - 口座から出る額 = 各カテゴリの見込み額 − そのカテゴリのカード払い分（予算ベース）
- **振り分け**: 口座払いの項目（予算）とカード引落を、口座ごとに集計する。

## 6. 技術構成

| 領域 | 採用 |
|---|---|
| ビルド | Vite + React + TypeScript |
| UI | MUI（Material UI）v7。テーマは OS のライト／ダークに追従 |
| DB | Dexie.js（IndexedDB）、`useLiveQuery` で画面を自動更新 |
| ルーティング | `#home` 形式のハッシュ（静的ホスティングと claude.ai の Artifact の両方で動く） |
| テスト | Vitest（計算ロジック中心） |
| 配布 | GitHub Actions → GitHub Pages。`npm run build:artifact` で1ファイル版も作れる |

### データ保全
- 起動時に `navigator.storage.persist()` を要求する。スマホではホーム画面に追加して使う。
- バックアップは JSON ファイルの保存と、テキストのコピー／貼り付けの両方に対応する（ファイル保存ができない環境向け）。
- 最後のバックアップから30日経つと「やること」に出す。

## 7. スプレッドシートからの取り込み（`src/domain/importSheet.ts`）

元の年間お金計画表のシートを読み込む。スマホではシート全体のセルをコピーして貼り付け（タブ区切り）、パソコンでは CSV ファイルを選ぶ。どちらも同じ処理で読む（タブを含めばタブ区切り）。

- 見出し行（「1月」「5/15-6/14」）から月の列を見つける。年は取り込み時に指定し、12月の次の1月は翌年にする。「5/15」から月の開始日も読む。
- 収入の行 → 「収入」カテゴリの項目（「15日」などは入出金日）。
- 支出の行 → カテゴリ。「- 子」の行や「25日 | 名前」の行があれば、それらを項目にする（親の行は合計なので使わない）。子がなければ同名の項目を1つ作る。名前に「返済」は返済、「貯金・投資・積立」は貯金として扱う。
- クレカの行 → カード（引落日つき）。今月より前の月の金額は確定した請求額として入れる。
- 集計行（「◯◯合計」）と、クレカより後（経費精算・バッファ・振り分けなど）は読まない。
- 金額は最後の月の値を「いつもの金額」にし、違う月はその月だけの予算（Entry）にする。
- 「置き換える」と「追加する」（同じ名前に足す。別の年のシートを続けて入れる用）を選べる。
- 口座、項目の支払い元（カード払いかどうか）はシートの値からは分からないため、取り込み後に設定で登録する。

## 8. 今後の候補

| 候補 | メモ |
|---|---|
| PWA（オフライン動作） | Service Worker。GitHub Pages 版のみ |
| 返済の残高と完済予定 | 定期項目の終了期から計算できる |
| 貯金目標の進み具合 | 貯金カテゴリの実績を積み上げる |
| 振り返りの推移 | カテゴリごとの予算差を複数期で並べる |
| Zaim CSV 取り込み | 手入力が負担になったら。Zaim カテゴリとの対応表が必要 |

## 変更履歴

- **v0.3.1**: 元のスプレッドシートを CSV で取り込めるようにした。
- **v0.3**: PoC を破棄し、同じ仕様で UI を MUI で実装し直した（計算ロジックとデータ層は引き継ぎ）。
- **v0.2.1**: 画面上の呼び方を「期」から「月」に。ホームの前期の振り返りカードを削除。
- **v0.2**: 記録は Zaim で行い、実績はカテゴリ合計の手入力に。年間表・給料日タブ・この先のバッファを廃止し、ホームの給料日モードに統合。カードの確定日とやること通知を追加。
- **v0.1**: スプレッドシートの分析と、最初の機能案（たたき台）。
